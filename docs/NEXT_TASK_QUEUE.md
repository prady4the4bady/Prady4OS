# NEXT_TASK_QUEUE — FIFO of ready-to-start work

**Operator directive 2026-08-23 §6.6.** The rule "task-switch during CI-wait,
never idle-stop" was correct but abstract, and abstract meant items got
re-picked or forgotten between sessions. This is the literal queue.

## How to use it

1. The moment a long QEMU campaign starts (which blocks all other QEMU use on
   this machine — §NON-NEGOTIABLE 12), **pop the top unclaimed item** and start
   its DDR or code-reading phase.
2. Mark it `[~]` with your session date when you start, `[x]` when its gate is
   green and pushed. Leave it `[ ]` if you only read.
3. **Append new work to the bottom**, never insert at the top — the ordering
   below encodes dependencies, and re-prioritising by insertion is how a queue
   stops being a queue.
4. Items marked **BLOCKED** name what unblocks them. Do not pop a blocked item.

Counts are generated by `tools/ci/status_report.sh`; do not hand-tally.
